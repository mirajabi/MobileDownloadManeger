Fetch documentation

Install it, then start a download.

This is the install path for Fetch, and for any app that downloads with the same library. Work through the chapters in order. Each code sample can show Kotlin or Java on its own, and the switch at the top sets every sample at once.

2Configure onceWrite the service settings before the first download. Do this from Application, or from the first screen.
3Enqueue a fileThe library saves the bytes. Your app still extracts the archive and installs the package.

Chapter 1

Where the call lives

The same request works from an Activity, a Fragment, a Worker, or a service you already run. Configure the library once. After that, enqueue and listen.

Calls you can paste

The Fetch source, file by file, lives on its own pages. From here down, each step is a library call. Open a sample and pick Kotlin or Java on that sample.

AFrom an Activity

Call configureService once, usually from the Activity that owns the screen, or from Application. After that the Activity only builds a request and listens. The byte window belongs on the request. Parallel connections belong on the saved config, through chunkCount.

class DownloadActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Parallel connections. chunkCount is how many ranges run together.
        DownloadForegroundService.configureService(this) {
            chunkCount(4)
            chunkParallel(true)
        }

        // Headers, including Cookie. There is no separate cookie field.
        val request = DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = "tms-app-release",
            headers = mapOf(
                "Authorization" to "Bearer token",
                "Cookie" to "session=abc"
            ),
            // Byte range. Both ends are inclusive. The saved file starts at local byte zero.
            rangeStart = 1_048_576L,
            rangeEndInclusive = 2_097_151L
        )

        DownloadForegroundService.registerListener(object : DownloadListener {
            override fun onCompleted(handle: DownloadHandle) {
                Log.i("MDM", "ready ${handle.id}")
            }
            override fun onFailed(handle: DownloadHandle, error: Throwable?) {
                Log.e("MDM", "failed ${handle.id}", error)
            }
        })
        DownloadForegroundService.enqueueDownload(this, request)
    }
}

BFrom a Fragment

A Fragment does not own the process. Use requireContext() and keep the download id in the Fragment so a button can pause that same transfer. Configure the service in the Activity, once. Calling it again from every Fragment only rewrites the same file.

class DownloadFragment : Fragment() {
    private val downloadId = "tms-app-release"

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        val context = requireContext()
        DownloadForegroundService.enqueueDownload(context, DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = downloadId,
            // Byte range, same meaning as in the Activity.
            rangeStart = 0L,
            rangeEndInclusive = 4_194_303L
        ))
        view.findViewById<Button>(R.id.pause).setOnClickListener {
            DownloadForegroundService.pauseDownload(context, downloadId)
        }
    }
}
public class DownloadFragment extends Fragment {
    private final String downloadId = "tms-app-release";

    @Override

                "https://downloads.example.com/tms/app-release.apk",
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                downloadId,
                Collections.<String, String>emptyMap(),
                null,

                // Byte range. Both ends are inclusive.
                0L,
                4_194_303L
        ));
        view.findViewById(R.id.pause).setOnClickListener(v ->
                DownloadForegroundService.pauseDownload(context, downloadId));
    }
}

CFrom a Worker

WorkManager should hand the file to the foreground service and return. The transfer keeps running after doWork ends. Build the request from the input data, including the byte window, so a retry of the work does not invent a different range.

class EnqueueDownloadWorker(
    context: Context,
    params: WorkerParameters
) : Worker(context, params) {
    override fun doWork(): Result {
        val start = inputData.getLong(KEY_START, -1L)
        val end = inputData.getLong(KEY_END, -1L)
        val request = DownloadRequest(
            url = inputData.getString(KEY_URL) ?: return Result.failure(),
            fileName = "app-release.apk",
            id = "tms-app-release",
            // Byte range carried in the work input. -1 means "not set".
            rangeStart = start.takeIf { it >= 0L },
            rangeEndInclusive = end.takeIf { it >= 0L }
        )
        DownloadForegroundService.enqueueDownload(applicationContext, request)
        return Result.success()
    }

    companion object {
        const val KEY_URL = "url"
        const val KEY_START = "range_start"
        const val KEY_END = "range_end"
    }
}
public class EnqueueDownloadWorker extends Worker {
    static final String KEY_URL = "url";
    static final String KEY_START = "range_start";
    static final String KEY_END = "range_end";

    public EnqueueDownloadWorker(@NonNull Context context, @NonNull WorkerParameters params) {
        super(context, params);
    }

    @NonNull
    @Override
    public Result doWork() {
        String url = getInputData().getString(KEY_URL);
        if (url == null) return Result.failure();
        long start = getInputData().getLong(KEY_START, -1L);
        long end = getInputData().getLong(KEY_END, -1L);
        DownloadRequest request = new DownloadRequest(
                url,
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                Collections.<String, String>emptyMap(),
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range from the work input. Null leaves that end open.
                start >= 0L ? Long.valueOf(start) : null,
                end >= 0L ? Long.valueOf(end) : null
        );
        DownloadForegroundService.enqueueDownload(getApplicationContext(), request);
        return Result.success();
    }
}

DFrom your own background service

If another component already runs in the background, it should not open the socket itself. Ask DownloadForegroundService to start. That service calls startForeground before it reads config or touches the network.

class TmsHandoffService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        val url = intent?.getStringExtra("url") ?: return START_NOT_STICKY
        DownloadForegroundService.enqueueDownload(this, DownloadRequest(
            url = url,
            fileName = "app-release.apk",
            id = "tms-app-release",
            // Byte range passed in by the caller. Omit both to take the whole file.
            rangeStart = if (intent.hasExtra("rangeStart")) intent.getLongExtra("rangeStart", 0L) else null,
            rangeEndInclusive = if (intent.hasExtra("rangeEnd")) intent.getLongExtra("rangeEnd", 0L) else null
        ))
        stopSelf(startId)
        return START_NOT_STICKY
    }

    override fun onBind(intent: Intent?): IBinder? = null
}
public class TmsHandoffService extends Service {
    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        if (intent == null || intent.getStringExtra("url") == null) return START_NOT_STICKY;
        Long start = intent.hasExtra("rangeStart") ? intent.getLongExtra("rangeStart", 0L) : null;
        Long end = intent.hasExtra("rangeEnd") ? intent.getLongExtra("rangeEnd", 0L) : null;
        DownloadForegroundService.enqueueDownload(this, new DownloadRequest(
                intent.getStringExtra("url"),
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                Collections.<String, String>emptyMap(),
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range. Null means that side is open.
                start,
                end
        ));
        stopSelf(startId);
        return START_NOT_STICKY;
    }

    @Override
    public IBinder onBind(Intent intent) {
        return null;
    }
}

Chapter 3 · Storage

Choose where the file lands

Auto tries app-specific external downloads, then documents, then filesDir/downloads. Scoped is a relative directory under external files. It is not a Storage Access Framework URI.

5Choose a destination

Pick one of the three shapes. Most apps can stay on Auto until they need a folder they can name.

    getExternalFilesDir(Environment.DIRECTORY_DOWNLOADS)!!.absolutePath
)

6Overwrite, free space, public Download

Free space is checked only when validation is on. The default floor is 10 MB. storageOverwrite(false) fails with StorageResolutionException if that file name already exists. A paused download of the same id is a checkpoint, so it does not trip this check.

DownloadForegroundService.configureService(this) {
    storageDestinations(listOf(DownloadDestination.Scoped("tms/packages")))
    storageOverwrite(false)
    storageValidateFreeSpace(validate = true, minBytes = 64L * 1024 * 1024)
    storageUsePublicDownloads(false)
}

Chapter 4 · Download

Build a request and enqueue it

url and fileName are required. Everything else has a default, and you can leave it alone until you need it.

8Build the request

Checksum hex length is 64 for SHA-256, 128 for SHA-512, and 32 for MD5. Blank or null means no checksum. A bad length fails in onFailed before any byte is written. rangeStart and rangeEndInclusive are optional and inclusive. Leave either one null to leave that end open. The older Java constructor still works; pass the two range arguments only when you want a window.

Chapter 7 · Control

Pause, resume, and stop

Pause writes the checkpoint first. That pause file stays until resume finishes or the user stops. Pause is not retried as a network error.

17Pause

Pass the same id you used on the request. The bytes already flushed stay on disk.

18Resume and stop

Resume continues from the saved offsets. A manual pause uses the pause record. A failed download uses the failed recovery record and continues from the bytes already flushed. A new enqueue of that same id still starts at byte zero. A changed strong ETag or total size discards the partial file first. Stop deletes the checkpoint. Reboot does not auto-start a failed download.

    }
