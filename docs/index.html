Sample app · module showcase

How Fetch uses every part of the library

Fetch is the app in showcase/. It does not add a second downloader. Each screen turns a choice into a public call on DownloadForegroundService or MobileDownloadManager. This course walks that source in the order the process actually runs, from the manifest to the home-screen widget.

The Kotlin / Java switch above changes the library reference further down the page. The Fetch course stays in Kotlin, because that is the language of the sample. The same calls appear in Java in the reference, starting at From an Activity.

Lesson 1

What the sample is

showcase/build.gradle.kts

The Gradle module is :showcase. Its application id is com.miaadrajabi.fetch, the launcher name is Fetch, and minSdk is 23, the same floor as the library. Inside this repository the app depends on the library as a project module:

implementation(project(":downloader"))

An app that is not this repository uses the published coordinate instead. That coordinate is com.github.mirajabi:MobileDownloadManeger:v1.3.7. Fetch never reaches into library internals. If a screen needs a download, it asks DownloadDesk.

The host still owns extraction and install. Fetch can open the system installer only when the engine switch promptInstaller is on. The library default, and the Fetch default, is off. An .apkm bundle is not an installable APK, so leaving that switch off is the right choice for a bundle.

Lesson 3

The manifest is the process boundary

showcase/src/main/AndroidManifest.xml

The application class is .FetchApp. The theme is Theme.Fetch. usesCleartextTraffic is true so an http:// lab URL is allowed. requestLegacyExternalStorage is present for older devices. On Android 11 and later the system ignores it, which is why a public Downloads path can still be unwritable and the library falls through to app-specific storage.

Permissions are the ones the library needs the host to hold: INTERNET, FOREGROUND_SERVICE, and the legacy storage pair. The download service itself is merged from the library manifest. Fetch does not declare a second download service.

  1. QueueActivity is the launcher. It is exported because the home screen starts it.
  2. ComposerActivity is also exported, with a SEND filter for text/plain. Share a link from another app and it lands in the links field as Intent.EXTRA_TEXT.
  3. SettingsActivity and FolderActivity are not exported. Nothing outside Fetch can open them.
  4. OfferActivity uses Theme.Fetch.Offer, a Material dialog theme. It is singleTop, excludeFromRecents, and not exported, so a second offer replaces the first and it never sits in the recents list.
  5. ClipWatchService is a plain service, not exported. It promotes itself to the foreground only after the user turns the clipboard switch on.
  6. FetchWidget is an AppWidgetProvider. The receiver is exported so the launcher can bind it. The metadata points at @xml/fetch_widget_info.

Lesson 4

What runs when the process starts

FetchApp.kt

Application.onCreate is the one place configuration is applied for the whole process. Four things happen, in this order:

  1. TransferStore reads the saved queue from fetch_queue.
  2. EngineSettings.load reads fetch_engine. A missing file uses the defaults on the data class.
  3. DownloadDesk.apply writes that engine into the library with configureService.
  4. DownloadForegroundService.registerListener(store.bridge) connects service callbacks to the rows. Listeners are not saved. They are registered again on every process start.
override fun onCreate() {
    super.onCreate()
    store = TransferStore(this)
    val settings = EngineSettings.load(this)
    DownloadDesk.apply(this, settings)
    DownloadForegroundService.registerListener(store.bridge)
    if (settings.watchClipboard) {
        ClipWatchService.start(this)
    }
}

The clipboard service starts here only when the saved switch is already on. Turning it on later happens in SettingsActivity after Save. Turning it off calls ClipWatchService.stopWatching, which stops the foreground notification.

Where a file is allowed to land

destinations() is the rule that stopped a relative name from becoming /Fetch at the root of the filesystem.

  1. auto returns DownloadDestination.Auto. The library picks the first writable place.
  2. scoped returns DownloadDestination.Scoped with the folder text, or Fetch when the field is blank. That folder lives under app-specific storage.
  3. custom returns DownloadDestination.Custom only when the text starts with /. A bare name such as Fetch is treated as Auto. File("Fetch") would otherwise resolve to /Fetch, which is not writable, and the download would fail before any byte moved.

The screen enforces the same split. Choosing Absolute path or App folder clears and disables Prefer public Downloads. Turning public Downloads on disables those two chips and shows the folder-inside-Downloads field. storageUsePublicDownloads is true only when both the switch is on and the destination is Auto. If that public folder cannot be created, the library continues in an app directory and reports the failure on the download instead of killing the process.

On Android 6 through 10, ComposerActivity.ensureStorage asks for the legacy storage permissions before a public download. On newer versions the request is skipped, because those permissions no longer grant a write to the public Downloads directory.

Lesson 6

DownloadDesk is the only library door

DownloadDesk.kt

Screens do not call the builder themselves. They call one of four methods, and each method starts by applying the current engine so a change on the settings screen is already on disk when the service starts.

apply

Sets the notification icon first, then configureService. enforceForeground(true) is always on in Fetch, so a running transfer keeps a foreground notification. schedulerUseAlarmManager follows the saved clock. configureService replaces the saved config. It does not shut the manager down.

enqueue

Applies the engine, then DownloadForegroundService.enqueueDownload. That is the Start now path. The service calls startForeground before it reads config or opens a socket.

schedule

Applies the engine with the clock the composer just chose, then scheduleDownload(context, request, whenToRun). ScheduleTime carries hour, minute, and either a calendar date or a weekday. This is a single run.

repeat

scheduleDownload always wants a clock time, so a repeat cannot use it. Fetch builds a manager, sets periodicSchedule(minutes), forces schedulerUseAlarmManager(false), and calls schedule(request, null). WorkManager raises anything under 15 minutes to 15. AlarmManager is not used for a repeat. After that, apply writes the normal engine back, so the one-shot clock flag is restored.

newRequest

Every row gets a new UUID as DownloadRequest.id. Destination on the request is Auto. The real folder comes from storageDestinations in the saved config, not from the request. Headers, checksum, algorithm, and the inclusive byte window are copied onto the request. A user-typed Range header is rejected in the composer, because the library strips that header and uses rangeStart and rangeEndInclusive instead.

previewPath

Before a byte moves, the composer asks StorageResolver where the file would land, with create = true so the folder exists. The path is shown as Saves as … and, when it starts with /, stored on the row as localPath. If no writable directory exists, the exception message is shown instead of a path.

Lesson 7

How a paste becomes addresses

LinkParser.kt

parse splits the text on whitespace. A token is kept when it starts with http:// or https://, after trailing commas, semicolons, and closing brackets are cut off. Duplicates are dropped. Anything else, including a ftp:// address, is ignored. The composer, the share intent, and the clipboard offer all use this one function, so they agree on what a link is.

fileNameFrom takes the last path segment, drops the query string, URL-decodes it, and keeps letters, digits, dot, underscore, and hyphen. A signed URL with a very long encoded name is shortened to 80 characters and the short extension is kept, so the file name stays a legal path. If the segment has no dot, the host is used, then .bin. An empty result becomes download.bin.

uniqueNames is used when several links are submitted together. One link may use the name typed in the field. Several links each take a name from their own URL, and a collision gets -2, -3, and so on before the extension.

Lesson 8

The new-download screen, field by field

ComposerActivity.kt · activity_composer.xml

The screen opens from the queue, from an empty-state button, or from a share intent. A share writes EXTRA_TEXT into the links field. Paste appends the clipboard under the text already there.

As the text changes, refreshLinks counts addresses. Zero links disables a useful start. One link lets the user edit the file name and shows the landing path. More than one link clears the file-name field and says each link keeps its own name.

What submit checks before it calls the library

  1. At least one http or https link.
  2. A header named Range or Content-Range is rejected. The byte fields are the range.
  3. A header name without a value is rejected. An empty name is skipped.
  4. Byte fields are empty or a whole number. Negative values are rejected. If both ends are set, the last byte must be the same as the first or later. Both empty means the whole file.
  5. Checksum is empty, or hex of the length the chip selected: 64 for SHA-256, 128 for SHA-512, 32 for MD5. A bad shape never reaches the service. The library would also fail a malformed checksum.
  6. A cookie is sent as the header Cookie. There is no separate cookie field on DownloadRequest.

The clock choice on this screen is saved back onto EngineSettings.useAlarm before the request is built, so WorkManager or AlarmManager matches the chips the user just touched.

For each URL the composer inserts a Transfer first, then calls the desk. The row exists before the first listener callback, with status queued and message Waiting to start, or scheduled and Waiting for the clock. The id on the row is request.id, so later callbacks find the same object. Then the activity finishes and the queue is what the user sees.

Lesson 10

The queue is a list of commands

QueueActivity.kt · QueueAdapter.kt

On start the activity tells FetchForeground that a screen is open, asks the store to locate files that may have moved, and watches the list. On stop it leaves the foreground count and drops the watcher, so a hidden activity does not keep redrawing. The recycler disables change animations so a progress tick does not flash the row.

The adapter does not call the library. It calls the lambdas the activity passed in. Those lambdas are the whole control surface:

onPause = { item ->
    DownloadForegroundService.pauseDownload(this, item.id)
    store.mark(item.id, TransferStore.STATUS_PAUSED, "Paused")
}
onResume = { item ->
    DownloadForegroundService.resumeDownload(this, item.id)
    store.mark(item.id, TransferStore.STATUS_RUNNING, "Resuming")
}
onStop = { item ->
    DownloadForegroundService.stopDownload(this, item.id)
    store.mark(item.id, TransferStore.STATUS_STOPPED, "Stopped")
}

The local mark updates the row immediately. The listener later confirms the same status when the service emits onPaused, onResumed, or onCancelled. Remove only deletes the row from fetch_queue. It does not delete the file and it does not call stop. Stop is the control that drops the recovery record.

Lesson 11

store.bridge is a DownloadListener. Fetch registers it once per process. Each callback finds the row with the same id and writes a status the adapter already understands.

touch ignores a callback for an id the queue does not have. It also refuses to move a saved, failed, or stopped row backwards, except when the update is allowed to leave a terminal state. onResumed is that case: a failed row is allowed to become running again.

Every change is written as JSON in fetch_queue and then posted to the main thread. Watchers redraw the list. The same snapshot is handed to FetchWidget.push, so the home screen follows the queue without a second listener.

locateFiles runs when the queue opens. If a row remembers a content URI from a move, and that URI can be resolved back to a filesystem path, localPath is updated. Open folder then uses the new place.

Lesson 12

Resume after a failure

QueueActivity · MobileDownloadManager.resume

A timeout, a dropped connection, or any other failure emits onFailed. The row becomes Failed and the adapter shows Resume. The button calls the same resumeDownload used for a manual pause.

Inside the library, resume looks in this order:

  1. If that id is already active, resume does nothing.
  2. If the id is in the in-memory pause table, it continues from those chunk offsets. That is the manual-pause path, and it is unchanged.
  3. Otherwise it loads the recovery record. When the record is FAILED, startFromRecord continues from the bytes already flushed. onResumed fires, and the row leaves Failed.
  4. If there is no failed record, resume returns false. Fetch has already marked the row Resuming. A later callback will correct it if the service does not start.

A new enqueue of an id that already failed still starts from byte zero. That rule did not change. Resume is the explicit continuation. Reboot still does not auto-start a failed download. Queued, running, and retry-waiting work continues from the last checkpoint. A manual pause stays paused.

A changed strong ETag or a changed total size still discards the partial file and starts at byte zero. A missing or weak ETag keeps the partial bytes. The checksum, when one was set, remains the final check.

Lesson 13

Copy, move, rename, and open the folder

QueueActivity.kt · SavedFiles.kt · FolderActivity.kt

These actions are Fetch, not the library. The library writes one file. The sample lets the user put a copy somewhere else.

Copy and move

Both open ACTION_CREATE_DOCUMENT with the current file name and a MIME type from the extension. The activity remembers the row id and whether this is a move, including across rotation. When the user picks a destination, Fetch tries to take a persistable read permission, copies the bytes on a background thread, and refreshes the row immediately with Copying… or Moving… so the list does not wait for the copy to finish before it shows the new state.

A successful move stores two things. locationUri is the content URI the user picked. localPath is the filesystem path decoded from a document id such as primary:Download/file, which becomes /storage/emulated/0/Download/file. Open folder then opens that new place. If the provider does not expose a path, the folder view uses the parent of the content URI.

Edit

The dialog edits the title shown on the row, the file name, and the URL. The URL must still start with http:// or https://. Copy link puts that URL on the clipboard. While a download is busy, only the title and the URL change. The file name stays locked so the writer and the row do not disagree. When the row is idle and the file is still at localPath, Save renames it in the same directory and stores the new path. A name that already exists is rejected.

Open folder

If the parent directory can be listed, FolderActivity shows the files and highlights the one that was downloaded. If the app cannot list it, Fetch tries ACTION_VIEW with the directory MIME type, using the parent of the content URI or a primary: document URI under external storage. The last fallback is still the in-app list, and if there is no directory at all the row says the folder is not available.

Lesson 14

A copied link can be offered

ClipOffer.kt · ClipWatchService.kt · OfferActivity.kt · FetchForeground.kt

The engine switch is watchClipboard, labeled Offer a copied link. It is off until the user saves it. This is not an accessibility service, and it is not a background reader of every app. Android 10 and later returns an empty clipboard to a process that is not in front, and Android 12 and later blocks a background activity start. Fetch follows that limit instead of pretending a dialog can always appear.

  1. FetchForeground counts visible Fetch screens. Queue, composer, settings, and folder each call enter in onStart and leave in onStop.
  2. While the switch is on, ClipWatchService runs as a foreground service with a low-importance notification, Watching for a copied link. The offer itself uses a second, high-importance channel so it can appear as a notification.
  3. On each clipboard change, and again in onResume of a Fetch screen, ClipOffer reads the text, runs LinkParser, and compares a SHA-256 of the raw text with the last offer stored in fetch_clip. The same copy is not asked twice.
  4. If a Fetch screen is open, OfferActivity shows Start this download? or Start these downloads? Start builds one request per link through DownloadDesk.newRequest and enqueue, with no extra headers and no byte window. Not now closes the dialog.
  5. If no Fetch screen is open, the service posts Start this download? Tapping it opens the same dialog, which is allowed because the user tapped a notification.

A SecurityException from the clipboard becomes an empty read. A failed startActivity from the service falls back to the notification.

Lesson 15

The home-screen widget

FetchWidget.kt · res/layout/widget_fetch.xml · res/xml/fetch_widget_info.xml

The provider is exported. fetch_widget_info asks for at least 180 by 72 dp and sets updatePeriodMillis to 0, so the system does not poll. Updates come from the app. TransferStore.publish calls FetchWidget.push after every queue change. Push skips the binder call when the status key is unchanged and the previous update was less than a second ago, so a fast progress stream does not rebuild the widget on every tick. A status change, such as running to failed, always goes through.

The widget shows the first queued, running, or retrying row: title, percent, and message. If nothing is active and a row has failed, it shows that file and the line Tap to resume a failed download. An empty queue says No download yet. The progress bar is indeterminate when a transfer is active but the percent is still unknown. The whole widget is one PendingIntent to QueueActivity. Resume itself stays on the row, because a widget tap should open the app rather than start a transfer with no confirmation.

Colors in the widget layout are explicit. RemoteViews does not resolve theme attributes reliably, so the background is widget_bg, a panel at #1C232D with a 22 dp corner.

Library reference

The same features, as calls

Configure the service once, then enqueue. Optional fields are filled with a real value and the default is named beside them. The host still extracts and installs. The library only downloads. Use the switch at the top to read every sample in Kotlin or in Java.

From an Activity

Call configureService once, usually from the Activity that owns the screen, or from Application. After that the Activity only builds a request and listens. The byte window is part of the request. Parallel connections are part of the saved config, through chunkCount.

Kotlin

class DownloadActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Parallel connections. chunkCount is how many ranges run together.
        DownloadForegroundService.configureService(this) {
            chunkCount(4)
            chunkParallel(true)
        }

        // Headers, including Cookie. There is no separate cookie field.
        val request = DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = "tms-app-release",
            headers = mapOf(
                "Authorization" to "Bearer token",
                "Cookie" to "session=abc"
            ),
            // Byte range. Both ends are inclusive. The saved file starts at local byte zero.
            rangeStart = 1_048_576L,
            rangeEndInclusive = 2_097_151L
        )

        DownloadForegroundService.registerListener(object : DownloadListener {
            override fun onCompleted(handle: DownloadHandle) {
                Log.i("MDM", "ready ${handle.id}")
            }
            override fun onFailed(handle: DownloadHandle, error: Throwable?) {
                Log.e("MDM", "failed ${handle.id}", error)
            }
        })
        DownloadForegroundService.enqueueDownload(this, request)
    }
}

Java

public class DownloadActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // Parallel connections. chunkCount is how many ranges run together.
        DownloadForegroundService.configureService(this, builder -> {
            builder.chunkCount(4);
            builder.chunkParallel(true);
            return kotlin.Unit.INSTANCE;
        });

        Map<String, String> headers = new HashMap<>();
        // Headers, including Cookie. There is no separate cookie field.
        headers.put("Authorization", "Bearer token");
        headers.put("Cookie", "session=abc");

        DownloadRequest request = new DownloadRequest(
                "https://downloads.example.com/tms/app-release.apk",
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                headers,
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range. Both ends are inclusive.
                1_048_576L,
                2_097_151L
        );

        DownloadForegroundService.registerListener(new DownloadListener() {
            @Override public void onQueued(DownloadHandle handle) { }
            @Override public void onStarted(DownloadHandle handle) { }
            @Override public void onProgress(DownloadHandle handle, DownloadProgress progress) { }
            @Override public void onPaused(DownloadHandle handle) { }
            @Override public void onResumed(DownloadHandle handle) { }
            @Override public void onCompleted(DownloadHandle handle) {
                Log.i("MDM", "ready " + handle.getId());
            }
            @Override public void onFailed(DownloadHandle handle, Throwable error) {
                Log.e("MDM", "failed " + handle.getId(), error);
            }
            @Override public void onRetry(DownloadHandle handle, int attempt) { }
            @Override public void onCancelled(DownloadHandle handle) { }
        });
        DownloadForegroundService.enqueueDownload(this, request);
    }
}

From a Fragment

A Fragment does not own the process. Use requireContext() and keep the download id in the Fragment so a button can pause the same transfer. Configure the service in the Activity, once. Doing it again from every Fragment just rewrites the same file.

Kotlin

class DownloadFragment : Fragment() {
    private val downloadId = "tms-app-release"

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        val context = requireContext()
        DownloadForegroundService.enqueueDownload(context, DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = downloadId,
            // Byte range, same meaning as in the Activity.
            rangeStart = 0L,
            rangeEndInclusive = 4_194_303L
        ))
        view.findViewById<Button>(R.id.pause).setOnClickListener {
            DownloadForegroundService.pauseDownload(context, downloadId)
        }

From a Worker

WorkManager should hand the file to the foreground service and return. The transfer itself keeps running after doWork ends. Build the request from the input data, including the byte window, so a retry of the work does not invent a different range.

Kotlin

class EnqueueDownloadWorker(
    context: Context,
    params: WorkerParameters
) : Worker(context, params) {
    override fun doWork(): Result {
        val start = inputData.getLong(KEY_START, -1L)
        val end = inputData.getLong(KEY_END, -1L)
        val request = DownloadRequest(
            url = inputData.getString(KEY_URL) ?: return Result.failure(),
            fileName = "app-release.apk",
            id = "tms-app-release",
            // Byte range carried in the work input. -1 means "not set".
            rangeStart = start.takeIf { it >= 0L },
            rangeEndInclusive = end.takeIf { it >= 0L }
        )
        DownloadForegroundService.enqueueDownload(applicationContext, request)
        return Result.success()
    }

    companion object {
        const val KEY_URL = "url"
        const val KEY_START = "range_start"
        const val KEY_END = "range_end"
    }
}

Java

public class EnqueueDownloadWorker extends Worker {
    static final String KEY_URL = "url";
    static final String KEY_START = "range_start";
    static final String KEY_END = "range_end";

    public EnqueueDownloadWorker(@NonNull Context context, @NonNull WorkerParameters params) {
        super(context, params);
    }

    @NonNull
    @Override
    public Result doWork() {
        String url = getInputData().getString(KEY_URL);
        if (url == null) return Result.failure();
        long start = getInputData().getLong(KEY_START, -1L);
        long end = getInputData().getLong(KEY_END, -1L);
        DownloadRequest request = new DownloadRequest(
                url,
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                Collections.<String, String>emptyMap(),
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range from the work input. Null leaves that end open.
                start >= 0L ? Long.valueOf(start) : null,
                end >= 0L ? Long.valueOf(end) : null
        );
        DownloadForegroundService.enqueueDownload(getApplicationContext(), request);
        return Result.success();
    }
}

class TmsHandoffService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {

            rangeEndInclusive = if (intent.hasExtra("rangeEnd")) intent.getLongExtra("rangeEnd", 0L) else null
        ))
        stopSelf(startId)
        return START_NOT_STICKY
    }

    override fun onBind(intent: Intent?): IBinder? = null
}

18Resume and stop

Resume continues from the saved offsets. A manual pause uses the pause record. A failed download uses the failed recovery record and continues from the bytes already flushed. A new enqueue of that same id still starts at byte zero. A changed strong ETag or total size discards the partial file first. Stop deletes the checkpoint. Reboot does not auto-start a failed download.

Kotlin

DownloadForegroundService.resumeDownload(this, "tms-app-release")
DownloadForegroundService.stopDownload(this, "tms-app-release")

25One writer per file

The same id and the same url, file name, and checksum reuses the active download or resumes a pause. A different healthy download on that path fails in onFailed with IllegalStateException and does not touch the file. A failed or cancelled download may be replaced from byte zero.

31What you observe

onCompleted is the only signal that the file is ready. Pause, stop, and a rejected second writer do not complete.

Kotlin

override fun onFailed(handle: DownloadHandle, error: Throwable?) {
    when (error) {
        is IllegalStateException -> { /* second writer rejected */ }
        is IllegalArgumentException -> { /* checksum shape rejected */ }
        else -> { /* network or integrity exhausted */ }
    }
}

Java

@Override public void onFailed(DownloadHandle handle, Throwable error) {
    if (error instanceof IllegalStateException) {
        // Second writer rejected.
    } else if (error instanceof IllegalArgumentException) {
        // Checksum shape rejected.
    }
}

Order of work: save the config, enqueue one request, wire pause and stop, then treat onCompleted as the file being ready for the host to extract or install.
