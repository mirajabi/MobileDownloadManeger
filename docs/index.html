Fetch, the sample app

The showcase module is a separate app. Paste one link or a whole list, then decide when it should start: now, in a few minutes, on a date, on a weekday, or on a repeat. The clock is WorkManager or AlarmManager. Chunks, the notification icon, storage, the installer prompt, and the file checks live on the engine screen. A finished row can copy or move the file, rename it, keep the original link, and open the folder it landed in.

Open the module in Android Studio and run it. The package name is com.miaadrajabi.fetch.

From an Activity

Call configureService once, usually from the Activity that owns the screen, or from Application. After that the Activity only builds a request and listens. The byte window is part of the request. Parallel connections are part of the saved config, through chunkCount.

Kotlin

class DownloadActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Parallel connections. chunkCount is how many ranges run together.
        DownloadForegroundService.configureService(this) {
            chunkCount(4)
            chunkParallel(true)
        }

        // Headers, including Cookie. There is no separate cookie field.
        val request = DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = "tms-app-release",
            headers = mapOf(
                "Authorization" to "Bearer token",
                "Cookie" to "session=abc"
            ),
            // Byte range. Both ends are inclusive. The saved file starts at local byte zero.
            rangeStart = 1_048_576L,
            rangeEndInclusive = 2_097_151L
        )

        DownloadForegroundService.registerListener(object : DownloadListener {
            override fun onCompleted(handle: DownloadHandle) {
                Log.i("MDM", "ready ${handle.id}")
            }
            override fun onFailed(handle: DownloadHandle, error: Throwable?) {
                Log.e("MDM", "failed ${handle.id}", error)
            }
        })
        DownloadForegroundService.enqueueDownload(this, request)
    }
}

public class DownloadActivity extends AppCompatActivity {

                Log.i("MDM", "ready " + handle.getId());

            }
            @Override public void onRetry(DownloadHandle handle, int attempt) { }
            @Override public void onCancelled(DownloadHandle handle) { }

From a Fragment

A Fragment does not own the process. Use requireContext() and keep the download id in the Fragment so a button can pause the same transfer. Configure the service in the Activity, once. Doing it again from every Fragment just rewrites the same file.

Kotlin

class DownloadFragment : Fragment() {
    private val downloadId = "tms-app-release"

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        val context = requireContext()
        DownloadForegroundService.enqueueDownload(context, DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            id = downloadId,
            // Byte range, same meaning as in the Activity.
            rangeStart = 0L,
            rangeEndInclusive = 4_194_303L
        ))
        view.findViewById<Button>(R.id.pause).setOnClickListener {
            DownloadForegroundService.pauseDownload(context, downloadId)
        }
    }
}

From a Worker

WorkManager should hand the file to the foreground service and return. The transfer itself keeps running after doWork ends. Build the request from the input data, including the byte window, so a retry of the work does not invent a different range.

Kotlin

class EnqueueDownloadWorker(
    context: Context,
    params: WorkerParameters
) : Worker(context, params) {
    override fun doWork(): Result {
        val start = inputData.getLong(KEY_START, -1L)
        val end = inputData.getLong(KEY_END, -1L)
        val request = DownloadRequest(
            url = inputData.getString(KEY_URL) ?: return Result.failure(),
            fileName = "app-release.apk",
            id = "tms-app-release",
            // Byte range carried in the work input. -1 means "not set".
            rangeStart = start.takeIf { it >= 0L },
            rangeEndInclusive = end.takeIf { it >= 0L }
        )
        DownloadForegroundService.enqueueDownload(applicationContext, request)
        return Result.success()
    }

    companion object {
        const val KEY_URL = "url"
        const val KEY_START = "range_start"
        const val KEY_END = "range_end"
    }
}

Java

public class EnqueueDownloadWorker extends Worker {
    static final String KEY_URL = "url";
    static final String KEY_START = "range_start";
    static final String KEY_END = "range_end";

    public EnqueueDownloadWorker(@NonNull Context context, @NonNull WorkerParameters params) {
        super(context, params);
    }

    @NonNull
    @Override
    public Result doWork() {
        String url = getInputData().getString(KEY_URL);
        if (url == null) return Result.failure();
        long start = getInputData().getLong(KEY_START, -1L);
        long end = getInputData().getLong(KEY_END, -1L);
        DownloadRequest request = new DownloadRequest(
                url,
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                Collections.<String, String>emptyMap(),
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range from the work input. Null leaves that end open.
                start >= 0L ? Long.valueOf(start) : null,
                end >= 0L ? Long.valueOf(end) : null
        );
        DownloadForegroundService.enqueueDownload(getApplicationContext(), request);
        return Result.success();
    }
}

From your own background service

If another component already runs in the background, it should not open the socket itself. It asks DownloadForegroundService to start. That service calls startForeground before it reads config or touches the network.

Kotlin

class TmsHandoffService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        val url = intent?.getStringExtra("url") ?: return START_NOT_STICKY
        DownloadForegroundService.enqueueDownload(this, DownloadRequest(
            url = url,
            fileName = "app-release.apk",
            id = "tms-app-release",
            // Byte range passed in by the caller. Omit both to take the whole file.
            rangeStart = if (intent.hasExtra("rangeStart")) intent.getLongExtra("rangeStart", 0L) else null,
            rangeEndInclusive = if (intent.hasExtra("rangeEnd")) intent.getLongExtra("rangeEnd", 0L) else null
        ))
        stopSelf(startId)
        return START_NOT_STICKY
    }

    override fun onBind(intent: Intent?): IBinder? = null
}

Java

public class TmsHandoffService extends Service {
    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        if (intent == null || intent.getStringExtra("url") == null) return START_NOT_STICKY;
        Long start = intent.hasExtra("rangeStart") ? intent.getLongExtra("rangeStart", 0L) : null;
        Long end = intent.hasExtra("rangeEnd") ? intent.getLongExtra("rangeEnd", 0L) : null;
        DownloadForegroundService.enqueueDownload(this, new DownloadRequest(
                intent.getStringExtra("url"),
                "app-release.apk",
                DownloadDestination.Auto.INSTANCE,
                "tms-app-release",
                Collections.<String, String>emptyMap(),
                null,
                ChecksumAlgorithm.SHA256,
                // Byte range. Null means that side is open.
                start,
                end
        ));
        stopSelf(startId);
        return START_NOT_STICKY;
    }

    @Override
    public IBinder onBind(Intent intent) {
        return null;
    }
}

Every feature in one place

This is the shape to copy when you want the whole library, not a slice of it. Comments name the feature. The byte window is optional: leave both ends null and the download is the whole file, which is what you want for an APK the host will install.

Kotlin

class TmsDownloadActivity : AppCompatActivity() {
    private val downloadId = "tms-app-release"

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        DownloadForegroundService.setNotificationIcon(R.drawable.ic_stat_download)
        DownloadForegroundService.configureService(this) {
            chunkCount(4) // Parallel connections.
            chunkParallel(true)
            chunkMinSize(256 * 1024L)
            retryPolicy(maxAttempts = 5, initialDelayMillis = 2_000L, backoffMultiplier = 2f)
            enforceForeground(true) // Foreground service while bytes move.
            notificationChannel("tms_downloads", "TMS downloads", "Package downloads")
            notificationIcon(R.drawable.ic_stat_download)
            notificationShowProgress(true)
            notificationPersistent(true)
            storageOverwrite(true)
            storageValidateFreeSpace(validate = true, minBytes = 32L * 1024 * 1024)
            storageUsePublicDownloads(false)
            installerPromptOnCompletion(enabled = false, fallbackMimeType = "application/vnd.android.package-archive")
            integrityValidation(
                verifyFileSize = true,
                verifyChecksum = true, // Checksum of the saved bytes, which is the window when one is set.
                verifyApkStructure = true,
                verifyContentType = false,
                verifyApkSignature = false
            )
        }

        val request = DownloadRequest(
            url = "https://downloads.example.com/tms/app-release.apk",
            fileName = "app-release.apk",
            destination = DownloadDestination.Scoped("tms/packages"),
            id = downloadId,
            headers = mapOf(
                "Authorization" to "Bearer token", // Headers.
                "Cookie" to "session=abc" // Cookie travels as a header.
            ),
            expectedChecksum = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
            checksumAlgorithm = ChecksumAlgorithm.SHA256,
            rangeStart = null, // Byte range. Null and null means the whole file.
            rangeEndInclusive = null
        )

        DownloadForegroundService.registerListener(object : DownloadListener {
            override fun onCompleted(handle: DownloadHandle) { }
            override fun onPaused(handle: DownloadHandle) { }
            override fun onFailed(handle: DownloadHandle, error: Throwable?) { }
        })
        DownloadForegroundService.enqueueDownload(this, request)
    }

    fun pause() = DownloadForegroundService.pauseDownload(this, downloadId)
    fun resume() = DownloadForegroundService.resumeDownload(this, downloadId)
    fun stop() = DownloadForegroundService.stopDownload(this, downloadId)
}

8Build the request

url and fileName are required. Checksum hex length is 64 for SHA-256, 128 for SHA-512, and 32 for MD5. Blank or null means no checksum. A bad length fails in onFailed before any byte is written. rangeStart and rangeEndInclusive are optional and inclusive. Leave either one null to leave that end open. The older Java constructor still works; pass the two range arguments only when you want a window.

25One writer per file

The same id and the same url, file name, and checksum reuses the active download or resumes a pause. A different healthy download on that path fails in onFailed with IllegalStateException and does not touch the file. A failed or cancelled download may be replaced from byte zero.

31What you observe

onCompleted is the only signal that the file is ready. Pause, stop, and a rejected second writer do not complete.

Kotlin

override fun onFailed(handle: DownloadHandle, error: Throwable?) {
    when (error) {
        is IllegalStateException -> { /* second writer rejected */ }
        is IllegalArgumentException -> { /* checksum shape rejected */ }
        else -> { /* network or integrity exhausted */ }
    }
}

Java

@Override public void onFailed(DownloadHandle handle, Throwable error) {
    if (error instanceof IllegalStateException) {
        // Second writer rejected.
    } else if (error instanceof IllegalArgumentException) {
        // Checksum shape rejected.
    }
}

Order of work: save the config, enqueue one request, wire pause and stop, then treat onCompleted as the file being ready for the host to extract or install.
