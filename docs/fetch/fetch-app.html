The process starts here

One class, one method. The queue is loaded, the saved engine is pushed into the library, and the listener is registered again because listeners are not written to disk.

FetchApp.kt · lines 1–21

onCreate

Order matters. The store exists before DownloadDesk.apply, and the listener is registered after configure, so the first callback has a list to update. Clipboard watch starts only when that switch was already saved. Turning it on later happens in settings, after Save.

package com.miaadrajabi.fetch

import android.app.Application
import com.miaadrajabi.downloader.DownloadForegroundService

class FetchApp : Application() {

    lateinit var store: TransferStore
        private set

    override fun onCreate() {
        super.onCreate()
        store = TransferStore(this)
        val settings = EngineSettings.load(this)
        DownloadDesk.apply(this, settings)
        DownloadForegroundService.registerListener(store.bridge)
        if (settings.watchClipboard) {
            ClipWatchService.start(this)
        }
    }
}
