# Desktop verification · 2026-10-16

Environment: macOS on Apple Silicon, Corretto JDK 17. The desktop build is independent of the repository-root Android build.

## Automated checks

```sh
cd multiplatform
./gradlew :engine:jvmTest :desktopApp:jvmTest
./gradlew :desktopApp:packageDistributionForCurrentOS
```

Both JVM suites passed: 55 engine tests and 39 desktop tests passed, with one fixture-dependent live-media test skipped (95 total). The native package task passed and produced the Apple Silicon DMG with its Java runtime and verified media helpers.

Coverage includes cancellation races, pause/resume byte integrity, writer checkpoints, checksum handling, media format parsing, paired video/audio choices, cancellation/timeouts, loopback player requests, palette contrast, compact layouts, sidebar resizing and collapse, inline expansion, context menus and invalidating stale URL checks.

The optional native playback and paired-download/merge tests also passed with a local MP4 fixture. They verify player start/pause/seek and that a paused two-track download resumes and produces a file containing both tracks. Regular CI skips these fixture-dependent tests.

The supplied public YouTube sample was extracted and both direct tracks verified during development. The supplied Instagram reel returned an audience restriction from the source. This is recorded as unavailable, not a successful extraction. Live service URLs expire and these checks are not a guarantee for every video.

## Visual review

The packaged Fetch.app was launched in an isolated demonstration home on macOS. Native captures of the main window, Add a download and Media Studio are published under `docs/desktop/images/`. No real download history was used.

The six theme images are captures of the actual Compose components with sample downloads, generated by `AppearanceTest`. They are labeled as sample renders on the website. The MacBook frame is website CSS, not a photograph of a physical computer.

Shell tests cover compact through wide layouts, density/text scaling and RTL. Additional UI-review images are generated under `desktopApp/build/ui-review/`. These are component tests, distinct from the packaged application captures.

## Remaining platform validation

- Windows and Linux native packages are configured in the installer workflow but have not been locally built or interactively reviewed on those systems.
- macOS signing/notarization and Windows signing are not configured.
- Intel macOS requires a separate Intel build.
- Physical-display DPI and VoiceOver navigation have not been manually tested.
- The Android and iOS shells need their own mobile product and release validation; the desktop UI is JVM/AWT/JavaFX-specific.
